# Translation (Arabic ⇄ English)

Arabic is the source language and the default. English is a lookup table keyed by the Arabic text, so the Arabic in the code stays readable and a missing English entry falls back to Arabic instead of breaking. The toggle lives in the app bar, on the login page and on the public evaluation page; the choice is saved in `localStorage` (`algo_lang`) and applied to `<html lang dir>` before the first paint (inline script in `index.html`).

## Files

| File | Role |
|---|---|
| `src/i18n/core.js` | Language state, `translate`, `translateData`, `translatedMap`, `getLocale`, `setLang` |
| `src/i18n/LanguageContext.jsx` | `LanguageProvider`, `useI18n()` → `{ lang, dir, isRtl, t, tr, td, setLang, toggleLang }` |
| `src/i18n/en/*.js` | English, one file per area. `common.js` shared words and client errors, `status.js` status/lifecycle/source labels and formatters, `server.js` backend-generated text and `SERVER_PATTERNS` |
| `src/components/LanguageToggle.jsx` | The switch: `variant="topbar"` (app bar) or `"pill"` (pages without the shell) |
| `scripts/i18n-check.mjs` | Coverage check (`node scripts/i18n-check.mjs [files] [--indirect] [--unused]`) |

## Writing UI text

```jsx
const { t, tr, td, lang } = useI18n();

<h1>{t('تسجيل الدخول')}</h1>                                  // JSX text
<input placeholder={t('ابحث بالاسم…')} aria-label={t('بحث')} />  // attributes
toast.success(t('تم حفظ التغييرات'));                            // strings in code
t('بعد {n} أيام', { n })                                         // values: {placeholders}, never template literals or +
tr('ينتهي بـ {hint}', { hint: <code className="ltr">{secret}</code> }) // an element inside a sentence
t(pluralAr(n, 'طالب واحد', 'طالبان', '{n} طلاب'), { n })          // plurals: English entries are functions of n
t('مطلوب|withdrawal-status')                                      // one Arabic word, two English meanings: context suffix (never shown)
td(notification.title)                                            // text from the server or DB (errors, notifications, ledger notes, seeded labels)
```

- Every component that shows text calls `useI18n()`. A component that does not, and whose parent does not re-render it, will not update when the language changes.
- Label helpers already translate when read: `StatusBadge`, `statusLabel`, `statusInfo`, `LEAD_STATUSES`, `*_STATUS_LABELS`, `SPECIALTY_LABELS`, `PRIVILEGE_LABELS`, `getSourceLabel`, `lifecycleStageLabel`, `COURSE_LIFECYCLE_STAGES[i].label`, `formatStageTiming`, `stageTimingHint`. Read them while rendering; a module-level copy (`const OPTIONS = Object.entries(PRIVILEGE_LABELS)…`) freezes the language it was built in.
- Dates, relative times, due labels and amounts (`formatDate*`, `formatRelativeTime`, `formatDueLabel`, `formatMinor`, `getCurrencyLabel()`) follow the language. Course tracks: `trackName(track)`.
- Keep Arabic keys in state and translate when rendering (`setError('أدخل الاسم')` → `{t(error)}`); API errors already arrive translated (`err.message`), show them with `td(err.message)` so a message caught before a language switch still reads correctly.
- `useMemo` / `useCallback` that build text list `t` (or `lang`) in their dependencies.
- Never translate data the user edits or the API receives: `labelAr`, `nameAr`, `currencyLabel`, codes, input values. User content (names, course titles, notes) is shown as entered.
- The Arabic key must match the English entry's `{placeholders}` exactly.

## Printed documents

A receipt can print in a different language from the screen. Document code gets its `t()` from `useDoc()` (`src/print/docContext.js`), which is built on `translateIn(lang, text, vars)` and `translateDataIn(lang, text)` from `src/i18n/core.js`; status labels use `statusLabelIn(lang, kind, value)`. The keys and dictionaries are the same as the UI's (`src/i18n/en/print.js` holds the document and print-dialog strings).

## RTL / LTR

Layout CSS uses logical properties only (`margin-inline-*`, `inset-inline-*`, `text-align: start`), so it mirrors automatically. For the rare physical case use `:root[dir='ltr'] …` (decorative gradients, the login field icons, the chat: English keeps own messages on the right like other chat apps). Icons that point a direction (`ChevronStartIcon`, `ChevronEndIcon`, `ArrowBackIcon`, `ArrowForwardIcon`) are drawn for RTL and carry `.icon-mirror`, which flips them in LTR; `SendIcon` is drawn for LTR and carries `.icon-mirror-rtl`.

## Checking

`node scripts/i18n-check.mjs` must finish without ERROR lines. A file whose Arabic is data rather than UI text (the Arabic number words in `src/print/amountWords.js`, the sample records in `src/print/sampleDocuments.js`) opts out with an `i18n-check: skip-file` comment near its top. It reports Arabic JSX text or attributes not wrapped in `t()`, Arabic template literals, strings with no English entry, placeholder mismatches, English values that still contain Arabic, and keys translated differently in two files. `--indirect` lists Arabic strings not passed straight to `t()` (constants, maps) for review. In development the browser console also warns once per missing entry.
